# 生成文本逃逸方法技术报告

队伍：666  
赛道：AI_Text Evasion

## 1. 任务理解

本赛道目标是在尽量保持文本语义不变的前提下，对机器生成文本进行改写或扰动，使其更难被生成文本检测器识别。根据赛道规则，标签含义如下：

- `0`：machine_text，机器生成文本，可修改
- `1`：human_text，人类写作文本，必须保持原样

提交文件要求为 UTF-8 编码 CSV，列名为：

```csv
prompt,text
```

在处理过程中，我们严格保持样本顺序不变，保持所有 `prompt` 不变，并且只修改 `label=0` 的机器文本。

## 2. 数据观察

我们对验证集进行了统计和抽样阅读。验证集共 12000 条样本，其中机器文本和人类文本各 6000 条，语种以英文为主，同时包含中文、俄文、保加利亚文、印尼文等多语种样本。

观察到机器文本中较常出现以下特征：

- 过于规整的解释结构
- 模板化连接词，例如 `Furthermore`、`Moreover`、`In conclusion`
- 句长较均匀，段落组织较机械
- 学术或百科式表达中常出现固定句式
- 对 prompt 的响应较完整但缺少自然文本中的格式扰动

人类文本则更常出现：

- 引用、列表、换行、评论式表达
- 局部不完整或不均匀结构
- 更自然的短句与长句混合
- 非模板化的转折和总结方式

基于这些观察，我们设计了两类逃逸操作：语篇层面的轻量人类化改写，以及字符/格式层面的检测器扰动。

## 3. 方法设计

### 3.1 规则人类化改写

第一阶段对机器文本做轻量人类化处理，目标是降低 AI 生成文本中常见的模板感，同时避免改变事实和语义。

主要规则包括：

1. 模板短语替换

```text
It is important to note that -> One thing worth noting is that
Furthermore -> Also / Another point is
Moreover -> Also / Besides that
In conclusion -> Overall / In short
Firstly / Secondly / Lastly -> 更自然的顺序表达
utilize -> use
facilitate -> help
demonstrate -> show
```

2. 长句拆分

对部分过长英文句子，根据逗号、`which`、`because`、`while`、`and` 等位置进行温和拆分，使句长分布更接近人类写作。

3. 段落扰动

对没有换行且句子较多的文本，随机加入少量段落分隔，减少大段连续说明文本的机器感。

4. 轻量 contractions

在英文文本中少量引入自然缩写，例如：

```text
do not -> don't
does not -> doesn't
cannot -> can't
```

对于非拉丁语种文本，我们采用更保守策略，只进行少量段落和标点层面的变化，避免破坏语义。

### 3.2 字符与格式扰动

第二阶段使用字符级与格式级扰动，目标是影响检测器的 tokenizer、字符统计特征和 embedding 表示。

主要操作包括：

1. Homoglyph 替换

将部分英文字母替换为视觉上相似的 Unicode 字符，例如：

```text
a -> а
e -> е
o -> о
p -> р
A -> А / Α
O -> О / Ο
```

这些替换对肉眼阅读影响较小，但会改变 tokenizer 的切分结果。

2. 单词首字母大小写扰动

随机改变少量英文单词首字母大小写，制造自然噪声。

3. 空格扰动

随机插入少量额外空格，影响空白符统计和 tokenizer 行为。

4. 标点扰动

对少量逗号、句号和模板连接处进行轻微调整，例如增加段落间隔或替换局部连接方式。

## 4. 参数选择

我们设计了多组扰动强度，并使用本地代理检测器在验证集抽样上进行参数搜索。最终采用如下参数：

```text
homoglyph_rate = 0.45
space_rate = 0.08
case_rate = 0.04
punctuation_rate = 0.20
```

参数搜索结果显示，过强扰动不一定带来更好的逃逸效果，同时会增加可读性风险。因此最终选择了检测逃逸效果和文本可读性之间较均衡的一组参数。

## 5. 实现流程

完整流程如下：

```text
读取原始 CSV
-> 清洗 BOM 表头
-> 遍历样本
-> 若 label=1，原样保留
-> 若 label=0，执行规则人类化改写
-> 对改写后的机器文本执行字符与格式扰动
-> 保持 prompt 和样本顺序不变
-> 输出 prompt,text CSV
```

核心脚本：

- `scripts/humanize_rules_evasion.py`
- `scripts/evasion_233style.py`

最终输出：

- `results/666_test_1.csv`
- `results/666_test_1.zip`

## 6. 本地验证

我们使用两类本地代理检测器进行验证：

1. 轻量字符 n-gram 检测器
2. RoBERTa embedding + KNN 检索式检测器

### 6.1 轻量检测器结果

在验证集上，检测器 AUC 和机器文本平均人类概率如下：

| 方法 | AUC | 机器文本平均人类概率 |
|---|---:|---:|
| 原始文本 | 0.7726 | 0.3283 |
| 字符扰动 | 0.7637 | 0.3733 |
| 规则人类化 + 字符扰动 | 0.7609 | 0.3873 |

逃逸目标是降低检测 AUC，并提升机器文本被判为人类文本的概率。因此组合方法优于单独字符扰动。

### 6.2 检索式检测器抽样结果

在每类 50 条、共 100 条样本的抽样测试中：

```text
原始机器文本平均人类概率：0.1790
攻击后机器文本平均人类概率：0.6104
提升：+0.4314
人类文本变化：0
```

该结果表明，方法能够显著提高机器文本在代理检测器上的人类概率，同时保持人类文本完全不变。

## 8. 方法特点

本方法具有以下特点：

- 不依赖外部 API，能够本地批量运行
- 多语种文本采用保守处理，降低语义破坏风险
- 结合语篇层和字符层扰动，兼顾自然性与检测逃逸效果
- 严格遵守只修改机器文本的规则
- 支持参数化调整，便于后续根据反馈继续优化

## 9. 局限性

当前方法仍存在一些限制：

- 若检测器进行 Unicode 归一化、大小写归一化和空白符合并，部分字符级扰动效果会下降
- 规则改写主要针对英文模板表达，对非英文文本提升较有限
- 未进行真实线上 test1/test2 反馈验证
- 若人工检查对 homoglyph 较敏感，需要降低字符替换比例

后续可进一步加入逐样本候选生成与代理检测器筛选，针对不同语种、文本长度和 prompt 类型使用不同扰动强度。
